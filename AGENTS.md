# Правила работы с этим репозиторием для агентов

Что здесь лежит и как устроено -- в `README.md`.

## Git здесь -- только руками человека

Агент **никогда** не выполняет в этом репозитории команды, меняющие индекс,
историю или рабочую копию:

    git add       git commit     git push      git pull
    git reset     git checkout   git restore   git stash
    git rebase    git merge      git cherry-pick
    git mv        git rm         git branch    git tag

Индексом и коммитами управляет только человек. Агент правит файлы -- и на этом
останавливается, перечислив, что именно изменил и где. Решение, что, когда и
какими кусками коммитить, принимает человек, а не агент.

Читать состояние можно и нужно: `git status`, `git log`, `git diff`, `git show`,
`git blame`, `git ls-files` -- всё, что не пишет, разрешено.

Переименование файла делается обычным `mv`, а не `git mv`: человек сам решит,
как оформить это в коммите.

Если кажется, что без коммита задачу не закончить -- значит задача заканчивается
до коммита. Сказать об этом и остановиться.

## systemd-юниты

`~/.config/systemd/user` -- симлинк на `dot-files/.config/systemd/user/`, поэтому
правка `.service` или `.timer` в репозитории меняет работающий юнит сразу.
systemd держит разобранные определения в памяти и сам их не перечитывает, так
что после правки **содержимого** юнита нужно:

    systemctl --user daemon-reload
