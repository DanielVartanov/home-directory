# .home-directory

Домашний каталог как git-репозиторий.

    bin/                   скрипты; ~/.local/bin -- симлинк сюда целиком
    dot-files/             дот-файлы; раскладываются симлинками по ~/
    lib/                   код, который слишком велик для одного файла в bin/
    installation-scripts/  установка машины с нуля, по скрипту на задачу

Установка с нуля описана в шапке `installation-scripts/_run-tty-part`
и `installation-scripts/_run-x-server-part` -- он же и вызывает все
остальные скрипты по очереди.

Скрипты из `installation-scripts/` рассчитаны на **однократный** запуск -- при
установке новой машины. Это не идемпотентные «применялки» конфигурации, их не
прогоняют повторно, чтобы подтянуть изменения. Всё, что нужно уже живой машине,
делается на месте: файл в репозитории и есть работающий файл.

Два каталога линкуются целиком, а не по файлу, и оба это делает `make-dirs`:

    ~/.local/bin           -> bin/
    ~/.config/systemd/user -> dot-files/.config/systemd/user/

Для systemd это значит, что новая фоновая задача -- просто два файла, положенных
в репозиторий, без всякой линковки. Побочно туда же попадает
`timers.target.wants/`, который создаёт `systemctl --user enable`: симлинки в нём
относительные, так что «какие таймеры включены» тоже версионируется и переезжает
на новую машину само. Обратная сторона: `systemctl --user enable` и `disable`
теперь меняют рабочую копию, и это видно в `git status`.
